# Contributing to IDA

Start from a named scientific question or engineering requirement. Link the relevant atlas record, manuscript version and requirement ID. State the expected observation and what would make the idea fail before reporting a result.

For a dataset: record source/version, access permission, license, species/population, modalities, montage/reference, time units, events, repeated sessions, treatment assignment, independent outcomes and overlap with prior datasets. Do not commit raw restricted or identifiable data, access tokens, private reports or unlicensed manuscript copies.

For analysis: separate exploration from held-out evaluation, preserve participant/session/site splits, keep preprocessing and model selection within training folds, and distinguish prediction, association and causal action value. Report negative and ambiguous findings.

For hardware: propose a requirement and test before a substitution. A schematic or mesh is not proof of physical safety, fit or clinical utility. Keep human-connected power and stimulation changes out of routine software contributions. Changes to intended use need an appropriate design review.

Run the Node core tests and Python engineering tests. Update the evidence status only when the matching test has actually been performed. This repository has no blanket open-source license yet; third-party materials retain their own terms. Ask the owner before redistribution beyond the chosen repository audience.
